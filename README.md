# Doublets

**Игра в словесные превращения на русском языке.**

Преврати одно слово в другое, меняя **ровно одну букву за ход**. Каждое промежуточное слово должно существовать в словаре.

```text
КОТ → КОД → ГОД
```

Слова — существительные в именительном падеже единственного числа, от 3 до 6 букв. **Е** и **Ё** считаются разными буквами. Проект написан на Python 3.10+.

## Где лежат готовые уровни?

> **⭐ `data/levels_approved.json` — главный файл с утверждёнными уровнями.**
>
> Здесь находятся уровни, прошедшие ручную проверку. **Именно этот файл следует использовать в игре.** Генератор не перезаписывает его автоматически.

Каждый уровень содержит начальное и конечное слово, минимальное количество ходов и пример кратчайшего решения:

```json
{
  "id": "level-001",
  "start": "год",
  "end": "кот",
  "min_moves": 2,
  "solution": ["год", "код", "кот"]
}
```

`solution` — **один из возможных** кратчайших путей, а не единственный правильный ответ.

## Как добавить новые уровни

Открой терминал в корне проекта (например, в PyCharm). Сначала создай отдельную Git-ветку от актуального `master`:

```powershell
git switch master
git pull origin master
git switch -c levels/batch-006
```

**1. Сгенерируй подборку одной командой:**

```powershell
python cli.py prepare-batch batch-006 --count 40 --seed 47
```

Появится файл `data/candidates/batch-006.json` с 40 кандидатами. Уже рассмотренные пары исключаются автоматически.

**2. Отправь подборку в GitHub:**

```powershell
git add data/candidates/batch-006.json
git commit -m "data: generate batch-006"
git push -u origin HEAD
```

**3. Передай ветку и номер подборки на проверку.** Ревьюер добавит подходящие уровни в `data/levels_approved.json`, а остальные решения запишет отдельно — в той же ветке.

**4. Проверь результат и создай Pull Request в `master`:**

```powershell
git pull
python cli.py validate-levels
python -m unittest discover -s tests -v
```

После успешной проверки слей PR вручную. **Не коммить напрямую в `master`.**

Для следующей подборки меняй номер (`batch-007`) и, для разнообразия, `--seed`. Seed управляет случайным выбором, **не сложностью**. По умолчанию подборки используют слова длиной **3–4 буквы** и решения от **2 до 5 ходов**.

## Карта файлов

| Где | Что это | Когда нужно |
| --- | --- | --- |
| **`data/levels_approved.json`** | **Утверждённые игровые уровни** | Для игры и релиза |
| `data/candidates/batch-*.json` | Сгенерированные подборки и история их проверки | Когда отбираем новые уровни |
| `data/quality/level_decisions.json` | Отклонённые и отложенные пары с причинами | Чтобы не рассматривать их снова |
| `data/quality/excluded_words.txt` | Стоп-лист непригодных слов | Когда обнаружено плохое слово |
| `data/processed/words_core.json` | Частотные слова для начала и конца уровня | Генератору |
| `data/processed/words_extended.json` | Более широкий словарь для построения цепочек | Генератору и проверке |
| `data/export/words.json` | Исходный экспорт словаря | Для пересборки словарей |
| `cli.py` | Все консольные команды | Для работы с проектом |
| `doublets/` | Логика словаря, поиска путей и генерации | При разработке |
| `tests/` | Автоматические тесты | Перед слиянием PR |

**Запомнить просто:** `candidates` — *предложения*, `levels_approved.json` — *готовый результат*, `level_decisions.json` — *история решений*.

## Экспорт для фронтенда

Когда каталог готов, собери три JSON-файла для отдельного игрового приложения:

```powershell
python cli.py export-game
```

Результат появится в локальной папке `game-data/`:

- **`levels.json`** — только утверждённые уровни;
- **`words.json`** — допустимые слова для проверки любых ходов, включая альтернативные решения;
- **`manifest.json`** — версия формата, правила, количество слов и уровней, SHA-256 файлов.

Экспорт **сначала проверяет весь каталог** и останавливается при ошибках. Слова из стоп-листа не попадают в `words.json`. Нужен подготовленный `data/processed/words_extended.json`; при его отсутствии сначала выполни `python cli.py quality` (см. ниже). Папка `game-data/` — генерируемый результат, её можно скопировать в репозиторий фронтенда.

## Полезные команды

```powershell
# Проверить все утверждённые уровни
python cli.py validate-levels

# Запустить тесты
python -m unittest discover -s tests -v

# Найти кратчайшую цепочку между двумя словами
python cli.py solve кот кит

# Посмотреть статистику исходного словаря
python cli.py stats
```

Для генерации нужны подготовленные файлы `words_core.json` и `words_extended.json`. Если их нет, см. раздел ниже.

<details>
<summary><strong>Дополнительно: откуда берутся слова и как пересобрать словарь</strong></summary>

Исходный словарь можно создать из установленного `pymorphy3`:

```powershell
python -m pip install -r requirements.txt
python cli.py build-pymorphy
```

Это перезаписывает `data/export/words.json`. Для очистки и подготовки рабочих словарей используется команда `quality`:

```powershell
python cli.py quality --frequency data/quality/frequency_ru.txt --min-frequency 1000
```

Она создаёт файлы в `data/processed/`. Частотный файл можно подготовить из собственного корпуса (`corpus-frequency`) либо импортировать из совместимого списка (`import-frequency`). Если частотного файла нет, команда `quality` может работать без `--frequency`, но основной словарь `core` не получит надёжного частотного отбора.

Техническая генерация без пакетного ревью тоже доступна через `python cli.py generate-levels --count 10 --seed 42`; результат `data/processed/levels.json` **не является утверждённым каталогом**.

При использовании сторонних словарных и частотных данных проверяй лицензии. Например, [FrequencyWords](https://github.com/hermitdave/FrequencyWords) использует данные OpenSubtitles 2018 под CC BY-SA 4.0. Частотность не доказывает, что слово понятно игроку или подходит для игры.
