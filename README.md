# Doublets — русский словарь и игровой движок

Первый этап Doublets: существительные в именительном падеже единственного числа, длина **3–6 букв**, буквы **Е** и **Ё** различаются. Каждый ход заменяет ровно одну букву. Python 3.10+.

## Быстрый запуск в PyCharm / Windows

В PyCharm выбери проектный Python и открой **Terminal**:

```powershell
python -m pip install -r requirements.txt
python cli.py stats
python cli.py analyze
python cli.py solve кот кит
python cli.py generate --min-moves 3 --max-moves 6 --seed 42
python -m unittest discover -s tests -v
```

В репозитории есть `data/export/words.json` в старом формате JSON-массива. CLI теперь читает и массив, и объект `{"words": [...], "rules": ...}`.

## Пересоздать словарь без сайта OpenCorpora

```powershell
python cli.py build-pymorphy
```

Для импорта используются установленные `pymorphy3` и `pymorphy3-dicts-ru`. Экспорт записывается в `data/export/words.json` в версионированном формате с метаданными. Существующий словарь будет перезаписан, поэтому при необходимости сохраните его копию. Альтернативный XML-импорт остаётся доступен:

```powershell
python cli.py build data/source/dict.opcorpora.xml
```

## Качество словаря

Результат первого анализа: **12 397 слов**, из которых 638 трёхбуквенных, 1939 четырёхбуквенных, 4019 пятибуквенных и 5801 шестибуквенное (из пользовательского запуска; не автоматически перепроверено CI).

Для анализа связности:

```powershell
python cli.py analyze
```

Для сохранения очищенной расширенной базы и кандидатов в основной словарь:

```powershell
python cli.py quality
```

По умолчанию `words_core.json` будет пуст: **частотный источник пока не подключён**, и мы не объявляем слова общеупотребительными без проверки. `words_extended.json` будет содержать все исходные слова кроме исключённых вручную.

Заполни `data/quality/excluded_words.txt`, по одному слову на строку. При наличии **лицензионно допустимого частотного файла** формата `слово число`:

```powershell
python cli.py quality --frequency data/quality/frequency_ru.txt --min-frequency 5
```

Создаются:

- `data/processed/words_core.json` — кандидаты в общеупотребительные слова по порогу частотности;
- `data/processed/words_extended.json` — расширенный список без ручных исключений;
- `data/processed/words_excluded.json` — реально исключённые слова;
- `data/processed/quality_report.json` — числа слов, рёбра, компоненты, изолированные слова, SHA256.

Частотный порог зависит от шкалы источника; это не универсальное значение. Частотность не гарантирует, что слово понятно игроку. Основной словарь требует редакторской проверки.


## Частотность из собственного корпуса (этап 3)

Подготовь собственный текстовый корпус: один UTF-8 файл `.txt` или каталог с несколькими `.txt`. **Тексты не включены в репозиторий**: используй только материалы, на которые у тебя есть право. Для локального корпуса удобно создать `data/source/corpus/` (он игнорируется Git).

```powershell
# Пример: собери свои тексты в data/source/corpus/*.txt
python cli.py corpus-frequency data/source/corpus --mode exact
python cli.py quality --frequency data/quality/frequency_ru.txt --min-frequency 5
```

Команда создаёт `data/quality/frequency_ru.txt` и `data/quality/frequency_ru.report.json`. В отчёте указаны число файлов, количество токенов, покрытие исходного словаря и SHA256 корпуса. Отчёт не публикуется автоматически. Значение порога **5** означает пять вхождений в выбранном корпусе, а не универсальную частоту слова.

По умолчанию `--mode exact` считает только **точные написания** слов из нашего словаря. Для учёта некоторых падежных форм можно попробовать `--mode lemma`, который использует наиболее вероятный разбор `pymorphy3`:

```powershell
python cli.py corpus-frequency data/source/corpus --mode lemma
```

Внимание: лемматизация неоднозначна; например, омонимы могут получить неправильный разбор. Если слово уже совпадает с формой в словаре, оно считается напрямую. Не используй частоты как автоматическое доказательство, что слово общеупотребительно или годится для уровня. Редакторская проверка обязательна.

Для маленького теста можно создать `data/source/corpus/demo.txt` с несколькими предложениями, затем проверить вывод. Маленький корпус годится только для проверки программы, не для оценки реальной частотности.

Новые тесты автоматически запускаются в GitHub Actions при открытии PR в `master`.

## Импорт большого частотного списка (этап 4)

Используем [FrequencyWords](https://github.com/hermitdave/FrequencyWords) (Hermit Dave, OpenSubtitles 2018). **Данные: CC BY-SA 4.0; код репозитория: MIT.** Исходные частотные данные не добавляются в Git. Соблюдай условия атрибуции и share-alike для производных данных, если будешь публиковать игровой словарь.

В PowerShell из корня проекта:

```powershell
New-Item -ItemType Directory -Force data/source | Out-Null
Invoke-WebRequest "https://raw.githubusercontent.com/hermitdave/FrequencyWords/525f9b560de45753a5ea01069454e72e9aa541c6/content/2018/ru/ru_50k.txt" -OutFile "data/source/ru_50k.txt"
python cli.py import-frequency data/source/ru_50k.txt --mode lemma
python cli.py quality --frequency data/quality/frequency_ru.txt --min-frequency 100
```

`--min-frequency 100` — **только стартовый порог** в количестве вхождений из субтитров, не «100 на миллион». Подбирай порог по графу, сравнивая `core_by_length` с `extended_by_length`. Можно запустить `--min-frequency 10`, `100`, `1000` и сравнить отчёты (при каждом запуске `quality` перезаписывает файлы).

Импорт учитывает точные совпадения со словарём и, при `--mode lemma`, некоторые падежные формы через наиболее вероятный разбор pymorphy3. **Омонимия остаётся**; частотный список не заменяет ручную проверку. `--mode exact` пригодится для сравнения без лемматизации. В `data/quality/frequency_ru.report.json` сохраняются SHA256 входного файла и показатели импорта.

Источники и лицензии: [FrequencyWords](https://github.com/hermitdave/FrequencyWords), [OpenSubtitles 2018](https://opus.nlpl.eu/OpenSubtitles2018.php), [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/). При публикации производного списка требуется отдельное решение о соблюдении условий лицензии; простой отказ от публикации исходника не отменяет их.

## Файлы

- `doublets/engine.py` — индекс соседей, BFS, проверка ходов и прототип генератора;
- `doublets/dictionary.py` — старый OpenCorpora XML importer и единая схема экспорта;
- `build_pymorphy_dictionary.py` — импорт из установленного pymorphy3;
- `doublets/dictionary_quality.py` — загрузка старого/нового JSON, фильтрация, графовая статистика;
- `cli.py` — консольный интерфейс;
- `tests/` — unit-тесты.

## Ограничения и дальнейшие задачи

1. Текущий словарь **не проходит редакторскую проверку**: могут встречаться редкие и спорные слова. Некоторые грамматические омонимы разрешены сознательно.
2. Необходимо проверить лицензию **самих словарных данных** и атрибуцию их источников; лицензия Python-пакета не обязательно распространяется на весь исходный корпус.
3. Уточнить политику буквы Ё (источник может содержать написания с Е вместо Ё).
4. Отобрать интересные пары и проверить не только концы, но и **все обязательные промежуточные слова**.
5. Создать офлайн-каталог уровней и оценку сложности после очистки.
6. `random_level` пока выбирает пары эвристически, а не равномерно среди всех допустимых пар.

**Git-процесс:** любые дальнейшие изменения делать в новой feature-ветке и предлагать через Pull Request в `master`. Не писать в `master` напрямую и не сливать PR без проверки.


## Генерация уровней с двумя словарями

После импорта частот и запуска `quality` (например, с `--min-frequency 1000`):

```powershell
python cli.py generate-levels --count 10 --min-moves 2 --max-moves 5 --seed 42
```

Команда читает `data/processed/words_core.json` и `data/processed/words_extended.json` и записывает `data/processed/levels.json`. Начальное и конечное слово выбираются из core, все переходы и минимальное решение вычисляются по extended. `seed` фиксирует результат для одинаковых входных словарей и параметров. Пары не повторяются в обратном порядке; если подходящих пар меньше запрошенного числа, генератор вернёт меньше уровней. Каждая запись содержит `start`, `end`, `min_moves`, `solution`.

Важно: пока это **технический генератор**, а не редакторски отобранные уровни. Core основан на частотности субтитров, extended содержит редкие слова; подсказки-решения могут включать трудные слова. Генератор также не оценивает число альтернативных путей или субъективную сложность.


### Редакторская проверка уровней (PR #5)

По умолчанию `generate-levels` берёт только слова длиной **3–4 буквы** и записывает `data/processed/levels_report.json`. Поле `quality.unfamiliar_intermediate_words` перечисляет промежуточные слова вне core; это **кандидаты на проверку**, а не автоматически ошибочные слова. Среди равных по длине кратчайших путей генератор сначала предпочитает меньше таких слов, затем большую суммарную частоту промежуточных слов. Это не изменяет минимальное число ходов.

Для ручного исключения слова добавь отдельную строку в `data/quality/excluded_words.txt` (например, `вов`, `бон`, `бод`). Генератор исключает их **до** поиска путей; уровень никогда не содержит исключённое слово. Для повторного формирования core/extended с этими же исключениями запусти `quality` заново.

```powershell
python cli.py generate-levels --count 10 --min-moves 2 --max-moves 5 --seed 42 --min-length 3 --max-length 4
```

Опции: `--exclude` (путь к стоп-листу), `--frequency` (локальный файл частот), `--report` (JSON-отчёт), `--min-length` и `--max-length` (3–6). Если частотного файла нет, предпочтение определяется только наличием слова в core. Для игрового релиза необходима ручная редактура и самих core-слов.


### Первичный редакторский стоп-лист

В `data/quality/excluded_words.txt` добавлен небольшой стартовый набор слов, замеченных при ручной проверке seed=42: грубая лексика и отдельные спорные формы. Это **не полный словарь ненормативной лексики** и не автоматическая лингвистическая классификация; список можно редактировать.

После обновления ветки обязательно пересоздай словари, иначе старые `data/processed/words_core.json` и `words_extended.json` останутся прежними. Сам `generate-levels` тоже читает стоп-лист и не пропускает эти слова даже при старых файлах.

```powershell
python cli.py quality --frequency data/quality/frequency_ru.txt --min-frequency 1000
python cli.py generate-levels --count 10 --min-moves 2 --max-moves 5 --seed 42
```

Из-за исключений результат для того же seed может измениться; это ожидаемо. Для релиза требуется дополнительная ручная проверка начальных/конечных слов и всех переходов.


### Отбор целых уровней

`generate-levels` теперь оценивает до `--candidate-limit 500` случайно перемешанных достижимых пар (фиксируемых `--seed`). Для каждой пары выбирается кратчайшая цепочка с предпочтением core-слов. Затем отбрасываются уровни с более чем `--max-unfamiliar 1` промежуточным словом вне core. Остальные сортируются по числу таких слов, минимальной частоте двух конечных слов и суммарной частоте промежуточных слов. Это **эвристика**, не гарантия нормативности или увлекательности.

```powershell
python cli.py generate-levels --count 10 --min-moves 2 --max-moves 5 --seed 42 --max-unfamiliar 1 --candidate-limit 500
```

Если подходящих уровней не хватает, попробуй `--candidate-limit 1500` или увеличь `--max-unfamiliar`. Увеличение лимита повышает время вычисления; результат может меняться при изменении лимита даже с тем же seed.


### Утверждённые уровни — стабильный каталог

`data/levels_approved.json` — версионированный (`version: 1`) **хранимый в Git** набор проверенных игровых уровней. Он отделён от временных кандидатов `data/processed/levels.json` и не перезаписывается генератором. Начальный набор содержит 5 уровней; новые уровни добавляются вручную с уникальным `id`, `start`, `end`, `min_moves` и `solution`. Сохранённый путь — пример оптимального решения, а не единственный разрешённый путь игрока.

```powershell
python cli.py validate-levels
python cli.py validate-levels --levels data/levels_approved.json --words data/processed/words_extended.json
```

Команда проверяет структуру каталога, уникальность ID и пар, разрешённость всех слов, переходы ровно в одну букву и кратчайшую длину решения с учётом стоп-листа. При ошибках печатает список и возвращает ненулевой код. Для проверки нужны локально созданные словари (`python cli.py quality ...`).

**Процесс пополнения:** сгенерировать кандидатов → вручную проверить слова и интересность цепочки → скопировать подходящий уровень в `data/levels_approved.json`, назначить ID → запустить `validate-levels` и тесты → включить изменение в PR. Не добавлять автоматически все результаты генерации.
